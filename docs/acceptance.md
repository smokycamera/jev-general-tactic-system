# 验收对应与边界

此表区分自动化能证明的行为和仍需真实环境验证的部分。

| 要求                 | 对应实现／验证                                                                   |
| -------------------- | -------------------------------------------------------------------------------- |
| 从启动到结束无需确认 | grid / regions 完整战斗测试；HTTP 创建默认自动运行；Chromium 监听所有 dialog     |
| 动态改案             | 目标变更、损失、通路阻塞、锁定与局部任务保留测试                                 |
| 模型故障继续         | 超时、网络、429、无效输出、过期响应、冷却与恢复测试                              |
| 人工介入优先         | 决策中暂停、合法手动命令、锁定、暂停后单步                                       |
| 能力差异             | 候选上限、分解预算、必要步骤保留、评价因素、协作与预案指标；单位数值保持不变     |
| 风格差异             | 十四维中性值与方向测试，实际路线和撤离目标测试                                   |
| 扩展无需改核心       | 注入新战法、新风格、新流程步骤；两种地图宿主                                     |
| 连续保存与恢复       | 重启续跑、动作已执行但确认未保存、临时文件中断、版本冲突、校验和、死亡写进程恢复 |
| 合法、去重、可复现   | 同时 step 串行化、同 key 宿主去重、固定种子、模型录制与回放                      |
| 机制缺失正常运行     | 未声明能力的旧适配器、显式禁用高级机制、可选步骤略过与依赖重接                   |
| 可扩展任务规划       | 新操作／新复合任务／新辅助战法、替代方法回溯、并行事实隔离、预算与环检测         |
| 协同执行             | 真实火力完成后开放突击、受阻分支修复、异步命令恢复与去重                         |
| 战术选择与偏好       | 五大类、32 个模板、10 种辅助战法；界面选择与不支持机制提示                       |
| 模型调用上限         | 普通动作默认本地执行、每次调度请求预算、无分类层级串行请求                       |
| 开箱运行             | 无密钥演示、本机服务、npm build、配置校验                                        |

代码内的 `confirmations:0` / `approvals:0` 是状态契约，不单独当作“零确认”的充分证据；完整自动战斗和浏览器 dialog 监听一起验证正常流程确实没有审批节点。

尚未作出的承诺：

- 已完成真实 Jev 合成场景联通，以及酒馆引擎经网关完成激活的冒烟；在线战术质量、限流及持续延迟未作基准测试，正文模型尚未实测。协议故障仍采用模拟响应验证。
- 酒馆适配已覆盖原有引擎测试、存档事务与合成浏览器宿主；未操作用户实际聊天，实际宿主和大型地图性能仍需验证。
- 当前实现是有预算的 HTN 分解、依赖执行与规则评分，不是搜索全场未来的完整博弈树；不保证大师在所有地图必胜。
- 演示采用完全可见战场、简化战斗结算；用户指挥目标与宿主胜负规则分开，改为撤退目标不会擅自修改宿主胜负条件。
- 回放成功模型响应可稳定重现动作；故障的墙钟冷却需要宿主的可控时钟才能严格重现原来的每个时间点。
