# 运行、保存与服务接口

## 静默运行

创建运行器后，在宿主战斗开始或激活事件调用 `notify()`，或者 `await start()` 运行到结束／等待事件。`step()` 用于宿主的一次调度；`singleStep()` 用于调试，会暂停自动循环并且只执行一次。正常流程不需要面板。

没有授权阵营行动机会或没有合法候选时进入 `waiting`。宿主下一次回合、观察、单位激活或目标变化后再次调用 `notify()`。宿主必须提供合法待命／结束行动动作；框架不会擅自把某个非法操作当成结束回合。

模型失败或预算耗尽，使用本地候选继续；有效评分按置信度连续降低权重，零置信度保留本地选择。连续失败后进入冷却；冷却结束后的下一次决策探测模型。宿主提交或保存持续失败，状态变为 `stopped`，停止提交，保留可恢复信息。宿主负责呈现非模态状态。

## 动作事务

1. 从宿主读取 `Observation.version`，取得授权单位的合法动作。
2. 选择后重新读取版本；取消、过期和不合法结果均不提交。
3. 将 `ActionEnvelope` 保存到检查点的 `pending` 字段。
4. 宿主检查 `sessionId` 与 `stateVersion`，按 `key` 去重并原子结算。
5. 保存宿主回执与新快照，清空 `pending`。

**去重必须由真实宿主持久化支持。** 如果宿主只能执行、不能查询已执行动作，框架无法凭本地文件单独保证跨进程的恰好一次结算。这里把要求明确写入 `BattleAdapter`，不以重试代替事务。

同一会话只启动一个控制器。每次请求取消只取消未提交的决策；已经开始的不可拆分宿主动作先完成，玩家修改在其后生效。模型请求不会持有宿主锁。

## 文件检查点

`FilePlanStore` 使用期望版本校验、串行写入、排他写锁、临时文件写入与 `fsync`、同目录原子替换，最后同步目录（Windows 跳过目录同步）。文件包含 SHA-256 校验和。

未完成的 `.tmp` 不作为恢复来源。写锁记录本机进程身份，确认原进程已退出时可以回收；无法识别锁归属或发现活跃写入者时停止写入，不抢占。损坏检查点报错，不覆盖为一场新战斗。

检查点保存计划、各任务进度、指挥官与风格、目标来源与版本、修订历史、模型记录、回执、待提交意图、宿主快照及指标。随机种子在示例宿主快照中。真实宿主通常不从该快照回滚战场。

恢复历史计划用 `restorePlan()`：把历史战法生成当前计划的新修订，按当前战场生成动作。真正的战场回档是宿主 `restore(snapshot)` 的独立操作，应在暂停状态进行，使用新的会话身份隔离旧命令。

## 本机服务

服务只绑定 `127.0.0.1`，默认 4317。密钥只在服务端读取。默认拒绝其他网页来源；酒馆接入时配置 `JEV_ALLOWED_ORIGINS`，建议同时配置 `JEV_SERVICE_TOKEN`，请求用 `Authorization: Bearer ...`。面板连接受令牌保护的服务时，可填写该本机令牌。

| 请求                    | 用途                                                                |
| ----------------------- | ------------------------------------------------------------------- |
| `GET /api/meta`         | 版本、能力、风格和战法定义                                          |
| `POST /api/sessions`    | `{kind:"grid"或"regions", id?:"稳定ID", auto?:true}`，默认自动运行  |
| `GET /api/sessions/:id` | 状态、计划、观察、指标、修订与回执                                  |
| `POST .../start`        | 恢复自动控制                                                        |
| `POST .../pause`        | 取消待处理决策，暂停后保存                                          |
| `POST .../step`         | 调试单步，完成后保持暂停                                            |
| `POST .../goals`        | `{goals:[...]}`，作为用户显式目标保存                               |
| `POST .../commander`    | `{id,ability,style}`，在下一决策边界修订                            |
| `POST .../lock`         | `{taskId,locked}`，可选锁定任务安排                                 |
| `GET .../actions`       | 当前合法手动动作列表                                                |
| `POST .../manual`       | `{actionId}`，从当前合法列表选取，立即取得优先权                    |
| `POST .../narrative`    | `{messages?:[{id,role,text,completed}]}`，主动扫描最近正文          |
| `POST .../restore-plan` | `{plan:历史计划}`，按当前状态生成新修订                             |
| `POST .../event`        | 演示故障注入：`{kind:"loss",unitId}` 或 `{kind:"blocked",location}` |
| `GET .../export`        | 导出完整 JSON 检查点                                                |

这些会话接口运行的是内置示例宿主。真实游戏接入要实现 `BattleAdapter`；当前服务不把任意网络 JSON 当成可信的真实战场。

## 任务执行与在线请求预算

每个计划可包含带依赖的任务网络。默认普通动作本地执行，maxModelCallsPerDecision 限制每次调度的模型请求总数。异步回执与执行终态分开保存，详见 [模块化任务规划](modular-tactics.md)。

动态目标绑定、搜索和有界行动历史见 [自适应规划](adaptive-planning.md)。
