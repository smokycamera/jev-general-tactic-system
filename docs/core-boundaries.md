# 核心边界与 0.2.1 审查

目标：让同一核心可被不同游戏宿主使用。此次发布不把酒馆的单位结构、技能规则、聊天 API、存档事务或 UI 放进核心。

| 层                            | 职责                                             | 不得依赖                                |
| ----------------------------- | ------------------------------------------------ | --------------------------------------- |
| packages/core                 | 计划、任务执行、模型预算、目标与上下文接口       | 酒馆、HTTP、模型 SDK、DOM、具体存档实现 |
| packages/providers            | 模型 SDK 和正文提取协议                          | 酒馆战斗引擎                            |
| apps/server                   | HTTP、Origin/令牌校验、无状态模型网关            | 酒馆动作与结算                          |
| tavern-battle/panel/src/jev-* | 真实战场映射、支援动作策略、原 AI 回退、聊天事务 | 修改内置核心源码                        |

相对上一版接入候选，审查后做了三个收敛：

1. 删除调度器中针对 `support` 动作的特殊分支。自定义执行器通过不带 stepId 的选项声明即时响应动作；它仍受单位授权、异步占用和任务租约约束，不冒充某个计划步骤完成。
2. 正文配置兼容、校验和提取结果过滤集中到 narrative.ts，主运行器只负责时序、预算、取消与提交。没有为不同宿主复制扫描分支。
3. 未知阵营过滤只约束模型提取结果，不再要求所有宿主目标的阵营都出现在当前可见单位中，避免破坏迷雾或暂时无单位的宿主。

保留的通用修复包括：按阵营首次激活建立计划、任务目标指纹、单位归属变化触发重建、零扫描窗口、10 次调用硬上限、取消时不提交过期扫描状态。

architecture.test.ts 遍历核心的静态与类型导入，禁止跨出核心目录、加载第三方/宿主模块或直接发起网络请求。reactive-actions.test.ts 用通用演示宿主验证新的执行器选项和异步占用，不借助酒馆完成测试。

这份审查确认本次改动的分层边界，不声称核心已经适配实时 RTS/FPS。现有回合与状态版本模型的实时化应独立设计和验证，未混入本次酒馆发布。
