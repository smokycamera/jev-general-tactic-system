# 架构与数据流

`packages/core` 是无 Node 专用依赖的决策库；`packages/demo` 是示例游戏宿主；`packages/providers` 在服务端请求模型；`apps/server` 管理会话和持久化；`apps/debug` 只是查看和主动干预的界面。

| 目录                         | 用途                                       |
| ---------------------------- | ------------------------------------------ |
| `packages/core/src/types.ts` | 所有公开接入契约                           |
| `registry.ts`                | 模块注册、能力配置、依赖循环和单位归属检查 |
| `runtime.ts`                 | 串行调度、取消、决策边界、去重、故障降级   |
| `planning.ts`                | 总计划、任务进度、修订和单位分工           |
| `doctrines.ts` / `styles.ts` | 十种战法和十四维风格                       |
| `scoring.ts`                 | 收益、风险、连续性与风格分项评分           |
| `goals.ts`                   | 目标来源优先级和正文窗口                   |
| `store.ts`                   | 保存契约与内存实现                         |
| `packages/demo`              | 方格和区域连接图、合法动作、可复现结算     |
| `packages/providers`         | Jev、可选正文模型与回放                    |
| `apps/server`                | 原子文件存储、配置校验、本机服务           |
| `examples/extensions.ts`     | 不改核心的扩展例子                         |

获取观察之后，默认流程依次运行：目标合并、态势评估、计划保留或修复、单位分工、合法候选生成、评分选择。提交与保存由运行器统一处理，扩展步骤不能绕过最终合法性和版本检查。

模块声明 ID、版本、依赖、输入输出字段、能力要求、预算和配置。`Workflow` 在启动时拒绝循环和缺失的依赖。自定义步骤通过 `extraStages` 注册，通过 `workflow` 选择；算法写在 TypeScript，JSON 只保存设置。

计划含三层节点：每个阵营的总目标、指挥官及其上下级指挥节点、各指挥官的战术任务。战法属于战术任务，进攻／防御／撤退属于该层内部的方案类别，和三层指挥关系分开。

每个单位只分配给一名直接指挥官。上级通过任务关系指挥下级，不重复取得下级单位的提交权。演示同时授权蓝、红两方，便于完整自动对战；真实宿主应只授权需要自动控制的一方。

核心不能访问隐藏信息。`Observation` 是宿主愿意暴露的范围；模型只接收这个范围。演示采用完全可见地图，真实迷雾、LOS、地形和胜负判定由适配器提供。

`TaskMethod` 是战法扩展点，提供适用条件、计划阶段、初步评分与动作偏好。未来阶段保存意图与条件，进入阶段后重新获得宿主合法动作，不预先提交未来行动。

`DecisionProvider` 不持有执行权。它只为已经生成的候选提供分值。运行器结合模型置信度和本地评分选择，最后重新读取宿主版本并复核动作。
